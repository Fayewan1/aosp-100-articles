1. TL;DR

查 Android 问题的信息源只有三个：官方文档、AOSP 源码、Gerrit。文档给公开契约，源码给真实行为，Gerrit 给「为什么改成这样」。栈帧是连接三者的最短路径：从 at android.app.ActivityThread.performLaunchActivity(...) 取类名，映射到 frameworks/base/core/java/android/app/ActivityThread.java，再 grep 方法名即可落到具体实现。查这些不需要编译、不需要真机，一棵源码树加 git/grep 就够。提问时把现象、复现、版本、已排除假设、关键栈帧这五样给全，别人才能回你。

3. 问题背景

应用崩溃日志里出现 at android.app.ActivityThread.performLaunchActivity(...)，你知道是启动环节的问题，但不知道这段代码在哪、谁调的、哪个版本改过。搜索引擎给的多是三年前的博客，示例代码和你树里的对不上。官方文档只写了 onCreate 该做什么，没写框架怎么调它。于是问题卡在「知道现象，找不到代码」。

4. 核心机制

4.1 概念与关系

三个信息源分工明确，栈帧是入口。

图 1：从栈帧定位源码的四步

  stacktrace 栈帧
        |
        v
  类名 -> 源码路径 -> grep 方法名
        |
        +--> 官方文档（公开契约）
        +--> Gerrit（变更与评审）

官方文档分两类：developer.android.com 的 API 参考、source.android.com 的平台文档。AOSP 源码是本树 1084 个 git 项目，行为以它为准。Gerrit 在 android-review.googlesource.com，看某个改动是谁提的、评审里怎么讨论的。

4.2 关键内容

栈帧定位法四步：读栈帧取类名，类名映射到包路径下的文件，在文件内 grep 方法名，读到实现。栈帧形如 at android.app.ActivityThread.performLaunchActivity(...)，ActivityThread 落在 frameworks/base/core/java/android/app/ActivityThread.java，本树实测该方法存在。这里的路径映射分两层：android.* 这类 public API 在 frameworks/base/core/java/ 下；com.android.server.* 系统服务不在 core/java，而在 frameworks/base/services/core/java/——例如 ActivityTaskManagerService 落在 services/core/java/com/android/server/wm/，按 core/java 拼路径会落空。

public API 的声明与实现在 frameworks/base/core/java/ 下。文档查不到的实现细节以源码为准；@hide 标注的接口不进公开文档，只能读源码。

报版本信息要两个值：

名称含义出处
BUILD_ID版本号build/make/core/build_id.mk
SDK_INTAPI 级别build/release/flag_values/trunk_staging/RELEASE_PLATFORM_SDK_VERSION.textproto（值 37；编译期取值，运行时以 ro.build.version.sdk 为准）

7. 常见问题与误区

7.1 误区

误区一：文档没写就是不支持。 错。文档覆盖公开契约，@hide 接口不进文档但源码里存在，实现细节一律以源码为准。

误区二：搜索博客比读源码快。 看起来对其实是错的。博客示例常对应旧版本，字段名和方法签名会漂移，读本树源码才能对齐你的环境。

误区三：查源码要先编译。 错。查文档与源码不需要编译、不需要真机，grep 静态读即可。

7.2 高频提问

问：栈帧里只有混淆后的类名怎么办？ 答：先看是不是应用自身代码，框架类名不会被混淆。 追问：框架类名也认不出呢？ 答：按包名前缀拼路径试 grep——android.* 这类 public API 在 frameworks/base/core/java/，com.android.server.* 系统服务在 frameworks/base/services/core/java/；拿不准就截取最后的类名在整个 frameworks/base/ 下 grep。

问：文档说的行为和源码不一致以谁为准？ 答：源码。 追问：想确认这是不是设计意图？ 答：去 Gerrit 搜相关符号名，看评审讨论。
