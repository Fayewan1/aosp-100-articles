1. TL;DR

launchMode 与 Intent 标志共同决定「这次启动是复用已有实例还是新建一个」以及「放进哪个任务栈」。判定发生在系统服务侧：ActivityStarter 先由 computeLaunchingTaskFlags 拼出任务相关标志，再由 resolveReusableTask 与 computeTargetTask 决定复用还是新建、归入哪个任务，复用时的清栈顶由 complyActivityFlags 执行。四档启动模式各有确切取值，singleTask 与 singleInstance 的差别不在「是否单例」，而在「是否独占一个任务栈」。任务栈本身是一组有序的 Activity 记录，不是抽象概念。

3. 问题背景

launchMode 是应用开发者最常被问倒的一块。常见的三种误判是：把 singleTask 当成「全局只有一个实例」；以为 singleTop 会阻止重复创建；以为设了 singleInstance 就不会再有别的 Activity 出现在同一任务里。这些误判在排查「返回键行为不对」「Activity 被意外清掉」时会把方向带偏。这一篇把判定逻辑落到具体代码，而不是停在口诀。

4. 核心机制

4.1 概念与关系

三个对象：任务（Task，一组按顺序排列的记录）、记录（ActivityRecord，每个 Activity 实例在系统侧的登记项）、启动模式（launchMode，写在清单里的复用策略）。

图 1：任务栈与启动模式的判定对象

  Task ──包含──▶ ActivityRecord ──按序──▶ 栈顶
   ▲
   └─ launchMode 与 Intent 标志决定新记录落在哪个 Task

关键点：决定权在系统侧。应用只是提供意图与声明，栈的形态由 ActivityStarter 判定。

4.2 关键流程

两种模式在任务结构上的差别如下：

图 2：singleTask 与 singleInstance 的栈形态差别

  singleTask：    Task T1 = [ A ][ B ]     再次启动 B ⇒ 清顶后复用
  singleInstance：Task T2 = [ B ] 独占     其它记录回到别的 Task

启动一次 Activity 时，startActivityUnchecked 依次做几件事。先由 computeLaunchingTaskFlags（约 3026 行）拼出任务相关的标志——它只负责 flag，不负责挑任务。接着由 resolveReusableTask（约 3130 行）在已有任务里找可复用的任务，找不到时才由 computeTargetTask（约 2306 行）决定新建或归入哪个任务。真正的复用判定落在 complyActivityFlags（约 2657 行）：若目标任务的栈顶就是同一条记录且模式为 singleTop，则复用；若是 singleTask 或 singleInstance，则在目标任务里查找已有记录，找到则以 performClearTop（约 2686 行）清掉其上的记录并复用，找不到才新建。对于复用的情况，系统调 deliverNewIntent 把新意图送到已有实例，这正是 onNewIntent 的来源。

任务创建与窗口参数的计算交给 Task 与 LaunchParamsController：前者登记任务属性，后者依据当前布局与来源窗口算出新记录应有的位置与尺寸。

4.3 一个具体例子

设 A 为入口（标准模式），B 声明为 singleTask。用户在 A 里启动 B，得到任务 T1（含 A、B）。若 B 内再启动 C，C 进 T1 栈顶。此时再次启动 B：ActivityStarter 在 T1 中找到已有 B，清掉其上的 C 并复用 B，同时把新意图交给 B 的 onNewIntent。用户按返回键看到的是 A，因为 C 已被清掉。

若把 B 改为 singleInstance，B 会独占一个任务 T2，C 则回到另一个任务。此时「返回」的落点与前者完全不同。这就是两种模式的分水岭：是否需要独占任务。

7. 常见问题与误区

7.1 误区

误区一：以为 `singleTask` 就是全局单例。 它的准确语义是「在所在任务内单实例，并把其上的记录清掉」，任务可以有多个，实例也可以存在于不同用户或显示设备上。

误区二：以为 `singleTop` 是防止重复创建的总开关。 它只在目标已是栈顶时复用；若目标在栈中间，仍会新建。

误区三（看起来对其实是错的）：以为 `singleInstance` 与 `singleTask` 只差一个「独占」的说法。 差别是结构性的：前者独占任务，后者与其他记录共处一个任务，返回落点因此不同。

误区四：以为复用实例不会走任何回调。 复用会走 onNewIntent，随后仍可能伴随状态迁移（见 AND-P1-102）。

7.2 高频提问

问：为什么设了 singleTask 还会出现新实例？ 答：若启动时带的标志要求另起任务，且目标任务不在同一显示或用户下，系统仍可能新建。判定见 resolveReusableTask 与 computeTargetTask，复用与清顶落在 complyActivityFlags。

追问：怎么确认实际落到了哪个任务？ 答：用 dumpsys activity activities 看记录归属，别只看清单声明。

问：onNewIntent 什么时候必须调用 setIntent？ 答：当后续逻辑依赖 getIntent() 拿到最新意图时。复用路径下旧意图仍在，若不更新会读到上一次的值。

追问：这是框架行为还是应用约定？ 答：框架不会自动替换，属应用侧约定，需自行处理。
