1. TL;DR

AOSP 不是一个大仓，而是 1084 个独立 git 项目拼成的树。树根的 .repo/manifests/default.xml 声明了 1087 个 <project>，多出的 3 个是 darwin 主机的预编译项目，Linux 上不同步。项目密度极不均匀：external 一个目录就占 557 个，超过全树一半。目录层级不表达依赖，manifest 的 path、remote、revision 才决定「谁在树的哪个位置」。理解这层关系，比记住任何单个模块都重要。

3. 问题背景

第一次打开 AOSP 源码树，ls 一下会看到 frameworks、packages、system、external 十几个顶层目录。想看窗口管理器在哪儿，凭直觉进 frameworks/base，确实在。换个目标，凭直觉就不灵了：有的代码在 packages 下的模块仓里，有的在 system 或 hardware 里。想找内核调度器代码，整个树翻遍也没有。真正的索引只有一份文件，藏在 .repo 里。

4. 核心机制

4.1 概念与关系

三个概念：manifest 声明「树里应该有什么」；git 项目是实际被同步下来的代码单元；linkfile 在树里制造符号链接，把某个仓内的路径伪装成另一个位置的稳定入口。

图 1：

manifest(声明) -> git 项目(实体) -> 树根工作区
                     |
                 linkfile(别名入口)

manifest 是意图，项目是实体，工作区是投影结果；三者对不上时按这个顺序回退查。

4.2 关键内容

配额与清单的差额是本篇最容易被误读的地方。wc -l .repo/project.list 得到 1084，而 manifest 里 <project> 有 1087 个。差额 3 个全部是 darwin 主机预编译项目（prebuilts/clang/host/darwin-x86 等三个），它们的 groups 含 notdefault 与 darwin，Linux 主机不同步。所以「声明数」永远 ≥ 「本地项目数」，差值取决于你选的 groups。

顶层项目数分布按 project.list 统计（2026-10-14 实测）：

名称含义出处
external557 个第三方与导入仓.repo/project.list
packages161 个应用与模块.repo/project.list
system88 个系统基础组件.repo/project.list
prebuilts70 个预编译产物.repo/project.list

其余：frameworks 36、tools 36、device 27、hardware 27、kernel 24、trusty 22、test 15、build 5、bootable 3、developers 2，另有 11 个目录各 1 个项目。

manifest 的关键属性：default revision 为 android17-release；remote aosp 的 fetch 是 ..；review 指向 android-review.googlesource.com；sync-j 为 4。fetch=".." 表示相对 manifest 仓自身位置解析远端地址，这是 repo 自举的常见写法。

linkfile 解决的是「路径搬家但入口不能变」的问题。<project path="build/make" name="platform/build"> 配 linkfile，把 build/make/envsetup.sh 链接成树根的 build/envsetup.sh。你在树根 source build/envsetup.sh 时，实际读的是 build/make 仓内的文件。

4.3 一个具体例子

把 1087 减去 3 得到 1084，与 project.list 行数完全吻合。再进一步：kernel/ 前缀的项目在 project.list 里是 24 个，全树含 kernel 的路径行共 31 个（多出的落在 device/linaro/*-kernel、trusty/kernel 等）。这 31 个绝大多数是预编译与配置（kernel/prebuilts/{6.1,6.6,6.12,6.18}/{arm64,x86_64}、kernel/configs、kernel/tests、prebuilts/qemu-kernel）；两个例外是源码与头文件仓：trusty/kernel（含 app/、include/、Android.bp）与 external/kernel-headers（导入的 Linux UAPI 头）。树内没有 Linux/GKI 内核源码。

7. 常见问题与误区

7.1 误区

错：1084 是 AOSP 的官方项目总数。 更正：1084 只是 .repo/project.list 行数，即本树当前 groups 组合下的已同步数。换主机、改 groups，这个数就变。

错：顶层目录名代表代码归属模块。 更正：目录是 manifest 的 path 决定的摆放位置，与仓名 name 可以不同，build/make 与 platform/build 就是一对。

错：kernel 就在树的 `kernel` 目录里。 更正：全树 31 个含 kernel 的项目里只有 trusty/kernel 是源码仓，没有 Linux/GKI 内核源码。

看起来对其实是错的：manifest 里 1087 个 `<project>` 就代表树里有 1087 个仓。 更正：声明包含 notdefault 与 darwin groups，Linux 上不同步那 3 个，实际只落 1084 个。

7.2 高频提问

问：.repo/manifest.xml 能改吗？ 答：不能，头部写明 DO NOT EDIT，它是 repo 在 init/sync 时生成的。追问：那要改配置改哪里？答：改 .repo/manifests/default.xml，再重新 sync。

问：fetch=".." 是什么意思？ 答：remote 地址相对 manifest 仓自身位置解析，不写死主机名。追问：为什么这么写？答：地址随 manifest 仓走，整套树连同 manifest 一起镜像搬迁时不用改远端配置。
