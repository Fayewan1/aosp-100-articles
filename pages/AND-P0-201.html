1. TL;DR

AOSP 不是一个大仓库，而是上千个独立 git 仓的集合，repo 是管这些仓的元工具。日常操作只有几条：repo init 建 .repo、repo sync 同步、repo start 开分支、repo forall 批处理。同步后 .repo/project.list 列出按当前 manifest 分组筛选后应存在的项目，本树 1084 行。真正决定同步行为的文件在 .repo/manifests/ 下，.repo/manifest.xml 只是生成物。

3. 问题背景

repo sync 跑完，屏幕上滚过几百行，然后你发现某个目录是空的。你以为是网络问题，重跑一遍还是空。另一种情况：想改同步的分支和并发数，顺手编辑 .repo/manifest.xml，下次 sync 后改动全没了。两个现象指向同一件事：没分清「生成物」与「输入源」。

4. 核心机制

4.1 概念与关系

四个概念：manifest（同步行为的输入源）、.repo（元数据目录）、project（一个独立 git 仓）、project.list（manifest 分组过滤后的项目清单）。

图 1：repo init 到同步取树的流程

repo init -u <url> -b <rev>
        |
        v
   .repo/manifests/ ---> .repo/manifest.xml (生成物)
                              |
                       repo sync -j N
                              |
                              v
                    各子仓 + .repo/project.list

4.2 关键内容

manifest 的关键属性定义了整棵树的基线，读 .repo/manifests/default.xml 可直接确认：

名称含义出处
default revision未显式指定时各仓共用的分支，本树为 android17-release.repo/manifests/default.xml
remote fetch远端地址前缀，aosp 为 ..同上
review代码评审站点同上
sync-j默认并发数，本树 4同上

同族命令的语义分工：

命令含义出处
repo init -u <manifest-url> -b <revision>拉 manifest 建 .reporepo 帮助
repo sync [-j N]按 manifest 同步各仓并写出项目清单repo 帮助
repo start <branch> --all在各仓建工作分支repo 帮助
repo forall -c '<cmd>'跨仓批处理repo 帮助

看单个仓时就是普通 git：在 frameworks/base 下执行 git 命令只影响该仓，跨仓一致性由 manifest 里各 project 的 revision 字段锁定。repo 工具自身也是一个 git 仓，位于 .repo/repo，入口 .repo/repo/repo，本树 HEAD 为 e1e215a（2026-09-23）。

4.3 一个具体例子

场景：某目录同步后为空。

先看生成物 .repo/manifest.xml：头部写明 DO NOT EDIT，全文约 514 字节，由 repo 在 init/sync 时生成。接着看输入源 .repo/manifests/default.xml，它的 revision 是 android17-release、sync-j 为 4。

再数 .repo/project.list：本树 1084 行，等于分组过滤后的全集（1087 − 3 notdefault），不等于成功清单。清单里没有的仓本地必为空——3 个 darwin 预编译项目因分组未选而不在其中；但清单内的项目也可能因 fetch 失败没落地，那才是故障。

7. 常见问题与误区

7.1 误区

误区一：改 `.repo/manifest.xml` 能改同步行为。 它是 init/sync 时生成的产物，下次同步即被覆盖；要改的是 .repo/manifests/ 下的 manifest。

误区二：目录是空的说明 sync 失败。 看起来对，其实常常是错的：不在 .repo/project.list 里的项目本来就不会落地，本树 3 个 darwin 预编译项目即属此类。

误区三：在某个子仓里用 git 能影响整棵树。 每个子仓都是独立 git 仓，跨仓一致性由 manifest 的 revision 字段锁定。

7.2 高频提问

问：repo sync 报错后，怎么知道哪些项目同步成功了？ 答：看 repo sync 的退出码与输出里的 Failing repos (network/checkout)；.repo/project.list 只说明本次 manifest 的范围，与 fetch 成败无关。 追问：那我怎么知道构建时哪些目录该有内容？ 答：以 manifest 的 project 全集减去 project.list，差集是分组未选的项目；清单内仍可能有 fetch 失败项，须核 sync 输出。

问：不编整棵树，只想用 lunch 选产品，要先做什么？ 答：先 source build/envsetup.sh，它是指向 build/make/envsetup.sh 的符号链接。 追问：不 source 行不行？ 答：不行，lunch 等函数由该脚本引入当前 shell。
