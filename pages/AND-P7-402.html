4. 核心机制

4.1 数据结构与状态定义

四个入口各自封装一类外设的获取与状态：BluetoothAdapter 表征本机蓝牙适配器（含 BR/EDR 与 LE），NfcAdapter 表征 NFC 控制器，UsbManager 管理 USB 设备/配件枚举，MediaProjection 是录屏/投屏的授权令牌。GATT（蓝牙低功耗属性协议）是 LE 设备通信的承载层。

图 1：四类外设的入口与远端落地

BluetoothAdapter -> bluetooth服务 -> 控制器(BR/EDR/LE/GATT)
NfcAdapter       -> nfcd          -> NFC控制器
UsbManager       -> usb子系统(内核) -> 设备/配件
MediaProjection  -> SurfaceFlinger -> VirtualDisplay(录屏)

7. 常见问题与误区

7.1 误区

  • 「蓝牙 startDiscovery 一定能搜到设备」。缺定位/蓝牙权限、适配器未启用、设备不可发现都会导致空集。
  • 「openDevice 失败是代码问题」。更常见是缺 USB_PERMISSION 或设备被占用，属权限与策略问题。
  • 「看起来对其实是错的」：以为 NfcAdapter.enable 一定能开 NFC。硬件缺失或系统策略禁用时它无法开启。
  • 「投屏黑屏是录制代码错」。更可能是 VirtualDisplay 的 Surface 未就绪或未授权，画面源为空。

7.2 高频提问

问：蓝牙搜不到设备先查什么？ 答：查 isEnabled（:1226）是否启用、定位/蓝牙权限是否授予、目标是否可发现；再查 startDiscovery（:1841）结果。 追问：已配对设备怎么取？ 答：getBondedDevices（:2425），不依赖实时扫描。

问：投屏黑屏怎么定位？ 答：确认 MediaProjection 授权通过、createVirtualDisplay（:167）返回的 Surface 已传给录制器；否则画面源为空。
